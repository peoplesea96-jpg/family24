# Family24 · 가족 일정 조율 캘린더

가족이 일정을 공유하고 시간을 조율하는 웹 서비스입니다. 기존 정적 목업을 보존하고, Python 서버·SQLite 저장소 및 P0/P1/P2 기능을 추가했습니다. 첨부 PRD 원본은 `family_calendar_prd_final.md`에 포함했습니다.

## 실행

Python 3.10 이상이 필요합니다. Windows PowerShell에서:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe server.py
```

브라우저에서 `http://127.0.0.1:8080`을 열고 회원가입 → 가족 생성 순서로 시작합니다. 기본 계정이나 비밀번호는 없습니다. 이메일 발송·외부 OAuth·유료 API는 사용하지 않습니다. Node.js는 테스트 실행에만 필요합니다.

서버를 종료했다 다시 실행해도 `data/family24.sqlite3`에 계정과 일정이 유지됩니다. 이 폴더는 Git에 포함되지 않습니다. 실제 데이터와 테스트 데이터는 분리합니다.

## 구현 기능

| 단계 | 기능                                                                                                                                                                                                                                                      |
| ---- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| P0   | 이메일·비밀번호 가입/로그인, 관리자 보조 재설정, 가족 생성·프로필·7일 초대·다중 관리자, 월간/주간 캘린더, 한국 공휴일, 일정 생성/수정/휴지통·복구, 공개 권한, 반복 일정, 참여 응답, 가용 시간과 후보 비교, 댓글·변경 이력, 내부 알림, 검색·필터, CSV/XLSX |
| P1   | 다중 가족 전환, 다크모드, 공개 범위 필터, 반복 간격·요일·매월 N번째 요일·횟수/종료일·개별 예외·이후 반복분 수정, 유형 아이콘, XLSX 5개 시트, 초대 폐기·프로필 연결·관리자 운영 이력                                                                       |
| P2   | 기간별 통계, 유형/구성원/요일 패턴 차트와 월별 집계, 계정별 개인화 설정, 날짜·장소·우선순위·정렬을 포함한 고급 검색, 목록 보기·주말/시간/공휴일 표시·밀도/시작 시간 설정, 기념일 전용 D-day 뷰                                                            |

P1/P2의 추상적인 항목은 위 표에 적힌 구체 기능으로 구현했습니다. 자동 시간 확정이나 AI 추천은 포함하지 않습니다. 분석은 현재 사용자가 볼 수 있는 일정의 집계입니다.

## 사용 규칙

- 기본 월간 캘린더는 월요일 시작이며 날짜 칸에 3개까지 표시합니다. 더보기로 날짜별 전체 목록을 확인합니다.
- 공개 범위가 ‘특정 가족’인 일정은 참여 대상과 작성자만 볼 수 있습니다. ‘나만 보기’는 작성자만 볼 수 있고 관리자도 우회할 수 없습니다.
- 주간 보기에서 조율할 일정을 고른 뒤 슬롯 클릭/드래그로 본인의 가용 시간을 등록합니다. 자세한 응답은 일정의 시간 조율 탭에서 비교합니다. 직접 시간 입력도 지원합니다.
- 후보 시간은 08:00~23:00 범위의 1시간 구간이며, 가능 인원 우선/불가능 인원 적은 순으로 여러 후보를 보여줍니다. 다른 시간·길이는 일정 수정 양식에서 지정할 수 있습니다.
- 반복 일정은 존재하지 않는 날짜를 건너뜁니다. 횟수는 제외한 회차도 포함해 계산합니다. ‘이번 일정만’은 예외 회차를 만들고, ‘이후 반복분’은 시리즈를 나누어 남은 횟수를 유지합니다. 반복 일정의 시간 확정은 선택한 회차만 분리해 확정합니다.
- 일정 전체 삭제는 반복 시리즈 전체에 적용됩니다. 한 회차만 취소하려면 ‘이번 일정만’ 수정에서 상태를 ‘취소’로 바꿉니다.
- 확정 일정의 날짜/시간/참여 대상/장소/반복 규칙이 바뀌면 조율 중으로 돌아가고 이력을 기록합니다.
- 초대는 7일간 유효한 일회용 코드/링크입니다. 특정 미연결 프로필용 초대는 참여 계정을 해당 프로필에 연결합니다.
- 비밀번호 재설정은 관리자가 본인 확인 후 1시간 유효한 일회용 코드를 전달하는 방식입니다. 기존 세션은 취소되며 사용자가 직접 새 비밀번호를 설정합니다. 관리자에게 비밀번호를 보여주지 않습니다.
- 휴지통/그룹 삭제 유예는 30일, 내부 알림은 90일입니다. 서버 시작 시와 실행 중 매시간 정리합니다. 서버가 꺼져 있는 동안에는 다음 실행 시 정리합니다.
- CSV/XLSX는 현재 기간·검색 조건·권한을 적용합니다. XLSX는 일정, 구성원, 일정 유형, 통계, 참여 응답으로 나뉩니다. CSV 수식 주입 방지와 XLSX 문자열 셀 처리를 적용했습니다.
- 일정을 동시에 수정하면 버전 충돌을 알려 덮어쓰기를 막습니다. 다른 사용자의 변경은 새로고침 버튼으로 가져옵니다.

## 구성과 데이터

- `server.py`: Flask API, SQLite 트랜잭션, 세션·권한 검사, 정기 정리, Waitress 실행
- `app.mjs`, `style.css`, `index.html`: 반응형 서비스 화면
- `core.mjs`: 반복 날짜 계산, 검색·집계, 외부 의존 없는 OOXML XLSX 생성
- `family_calendar_mockup.html`: 기존 정적 목업 원본 (변경하지 않음)
- `family_calendar_prd_final.md`: 제공된 PRD 원본
- `test_server.py`, `test_core.mjs`: 권한·인증·데이터 흐름·반복·검색·내보내기 검사
- `IMPLEMENTATION.md`: API와 운영 설정 및 검증 기록

SQLite의 계정·세션·가족·초대 테이블을 사용합니다. 가족별 문서에 구성원·유형·일정·가용 시간·댓글·이력·알림을 저장하고, 쓰기는 `BEGIN IMMEDIATE` 트랜잭션으로 직렬화합니다. 모든 일정은 가족 ID를 갖고 서버에서 가족 소속과 일정 공개 권한을 검증합니다.

## 검증

```powershell
.\.venv\Scripts\python.exe -m unittest -v test_server
node --test test_core.mjs
```

서버 21개와 날짜/검색/통계/XLSX 6개 검사가 통과했습니다. XLSX ZIP의 CRC와 전체 XML 구조도 확인했습니다. 브라우저에서 가입, 가족 생성, 반복 일정 저장 및 새로고침 유지, 조율 입력, 검색/통계와 화면 설정을 점검했습니다.

## 배포 상태

Render용 영구 디스크·HTTPS·상태 검사 설정을 `render.yaml`에 준비했습니다. 실제 서비스 생성에는 호스팅 계정 연결과 비용 승인이 필요합니다. 상세 절차는 [공개 배포 안내](DEPLOYMENT.md)를 참고하세요.

로컬에서 실행 가능한 서버 구현입니다. 외부 공개 서버 배포는 아직 하지 않았습니다. GitHub Pages는 Python/SQLite 서버를 실행하지 못하므로 실제 서비스 호스팅으로 사용할 수 없습니다. Pages에서는 보존된 `family_calendar_mockup.html`만 독립적으로 열 수 있습니다.

외부 배포에는 지속 디스크, HTTPS 역방향 프록시, 프로세스 상시 실행 및 DB 백업이 필요합니다. `FAMILY24_ORIGIN`을 실제 HTTPS 주소로, `FAMILY24_SECURE_COOKIE=1`로 설정해야 합니다. 운영 환경에서 부하·백업 복구·접근성 전수 검증을 별도로 진행해야 합니다.
